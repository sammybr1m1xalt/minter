REMAINING BUGS (C-F)
--------------------

Bug C (REMAINING): No startTime sort on eligible stages
  Location: fcfs-drops.ts assessDropEligibility
  Issue: Eligible stages are not sorted by startTime ascending before evaluation
  Upstream reference: getEligibleOpenWindow in opensea-drop.js sorts by startTime, then priceUnit
  Fix needed: Add .sort((a, b) => (a.startTime - b.startTime)) in assessDropEligibility

Bug D (REMAINING): eligibleMinterAddress returned but not checked
  Location: opensea-gql.ts getDropEligibility returns eligibleMinterAddress field
  Issue: Field is populated but wizard/fcfs-mint never verifies it matches walletAddress
  Impact: Potential false positives where eligibility response is for a different wallet
  Fix needed: Verify eligibleMinterAddress === walletAddress when present

Bug E (REMAINING): eligiblePrice not surfaced for price protection
  Location: opensea-gql.ts getDropEligibility returns eligiblePrice.token
    (unit, symbol, contractAddress, chain.identifier)
  Issue: Eligible price per stage is fetched but never passed to price-protection.ts
  Impact: Can't compare mint price against locked price or max price spec
  Fix needed: Thread eligiblePrice through to price protection checks

Bug F (REMAINING): accountStageEligibility.wallets array not iterated
  Location: opensea-gql.ts getDropEligibility returns accountStageEligibility.wallets
  Issue: Per-wallet stage eligibility (already minted max) never aggregated
  Impact: Can't accurately report "already minted max" — only checks single wallet
  Fix needed: Iterate wallets array in reportInventoryEligibility to find max minted count


NEW BUGS DISCOVERED (G-N)
-------------------------

Bug G (REMAINING): *** placeholder in wizard.ts (API key bypass) — CRITICAL
  Location: wizard.ts lines 818, 869, 1036, 1068, 1892, 1927
  Issue: openSeaApiKey: *** || undefined — *** is a redacted placeholder, NOT actual
         code. The real apiKey/signedApiKey variable is NOT passed to buildMintPlan
         or executeFcfsSnipe.
  Impact: Signed/allowlist mint paths receive "***" (or undefined) as API key instead
         of the real resolved key → all signed mints fail with auth errors
  Fix needed: Replace *** with the real apiKey / signedApiKey variable at each site

Bug H (REMAINING): Phase selection in runFcfsBranch — downstream of Bug C
  Location: wizard.ts line 1553 — targetable.sort() uses priority + startTime
  Note: Correct in isolation, but assessDropEligibility itself doesn't sort (Bug C)
  Fix needed: Same as Bug C — ensure assessDropEligibility sorts internally

Bug I (REMAINING): SIWE session warming only checks first wallet
  Location: wizard.ts line 1542 — reportInventoryEligibility(inventory, ourWallet, ...)
  Issue: Sessions warmed for ALL wallets (line 1533), but reportInventoryEligibility
         only called for ourWallet (wallets[0]). Other wallets' eligibility not checked.
  Fix needed: Loop through all wallets, call reportInventoryEligibility per wallet

Bug J (REMAINING): classifyMintMode casing mismatch
  Location: fcfs-mint.ts line 847-889 — classifyMintMode
  Issue: Checks drop.type === "signed_presale" but GQL returns SCREAMING_SNAKE_CASE
         (SIGNED_PRESALE). REST/JSON returns lowercase.
  Upstream reference: opensea-drop.js line 227 — stageType === 'SIGNED_PRESALE'
  Fix needed: Add both casings: drop.type === "signed_presale" || drop.type === "SIGNED_PRESALE"

Bug K (REMAINING): Unix ms timestamp support missing
  Location: mint-cli.ts parseWhen — handles 10-digit unix seconds, not 13-digit ms
  Per OPENSEC_API_LAYOUT.txt: 13-digit ms timestamps must be supported
  Fix needed: parseWhen should detect 13-digit input and divide by 1000

Bug L (REMAINING): Chain resolution from slug doesn't distinguish OpenSea drops
  Location: slug-resolver.ts resolveTarget
  Issue: When slug is provided, fetches collection metadata but assumes all slugs
         are OpenSea-managed drops. Generic collection slugs not handled.
  Fix needed: Distinguish OpenSea-drop slugs from generic collection slugs

Bug M (REMAINING): postMintTx error handling granularity
  Location: opensea-gql.ts postMintTx
  Issue: 404 on POST /drops/{slug}/mint treated as single case — could mean slug
         isn't a drop OR drop has ended. No distinction.
  Fix needed: Add explicit status code handling for 404 vs 422 vs other

Bug N (REMAINING): || "" audit across fcfs-drops.ts
  Location: fcfs-drops.ts lines 417, 529, 541, 545, 549, 595
  Issue: || "" fallback patterns remain after ethereum-chain cleanup. Audit required
         for legitimate field-name fallbacks vs data-masking patterns.
  Assessment: Most are legitimate alternate field names (stage_type || stageType),
         but review each for correctness.
